## 文档口径

- 本文件只保留“当前真实未闭环项”与“仍需跟踪的真实现象”。
- 已完成并已有稳定测试证据的事项，不再作为正文待办展开，只保留必要的证据引用。
- “无 `output_docx_path` 但命中当前真实模型测试白名单的结构化失败”属于受控失败，不等于通过，但也不应直接记为阻塞。
- 只有当问题导致无输出、关键阶段缺失、非白名单失败，或最终用户可见结果错误时，才升级为阻塞。

## 状态口径

- `待闭环`：能力缺口仍在，尚不能对外宣称该项稳定完成。
- `待跟踪`：现象真实存在，但当前已有可解释 diagnostics 或受控落点，暂不直接视为阻塞。
- `受控失败`：当前测试已允许的结构化失败，表示系统正确暴露了边界，不表示能力已完成。

## 当前差距待办事项

### P0：宿主 / 前端对 `src/langgraph-ts` 的主链接管尚未收口

- 当前现状：`README.md` 已明确当前系统仍是“legacy 宿主兼容层 + `src/langgraph-ts/` 新主链”，桌面 GUI、本地 Web API、TS CLI 桥接仍由旧宿主承担。
- 当前差距：`src/langgraph-ts` 已承载 runtime、projection、tooling 与 materialize 主链，但宿主入口、前端状态透传、diagnostics 展示和运行时边界仍未形成单一权威实现。
- 验收口径：宿主 / 前端直接以当前 graph 合同、projection 摘要和结构化 diagnostics 为准，不再依赖历史 runtime 语义解释当前行为。
- 阻塞判定：如果新增能力仍必须回到旧 runtime 语义补洞，或前端 / 宿主展示口径与 `src/langgraph-ts` 实际执行结果不一致，则视为未闭环阻塞。

### P0：模板写回稳定性与 `.rels` 调和仍未达到稳定交付口径

- 当前现状：`README.md` 仍明确提示模板链路在“解析 -> 改写 -> 写回”阶段可能产出损坏的 DOCX；`docs/phase4-handoff.md` 只覆盖了 settings、header/footer、image 等有限 relationship reconcile。
- 当前差距：模板工作区还不能按稳定生产链路对外宣称可用；复杂引用、更多资源类型和异常写回场景仍缺少可靠收口。
- 验收口径：目标模板样本在真实链路下应稳定产出可正常打开的 DOCX；无法支持的关系写入应返回结构化失败，而不是写出损坏文件。
- 阻塞判定：输出 DOCX 损坏、关系未调和导致文件不可打开，或出现无法解释的非结构化写回失败。

### P1：`semantic_selector` 仍是受限能力，扩展范围尚未闭环

- 当前现状：`README.md` 与 `docs/phase3-handoff.md`、`docs/phase4-handoff.md` 一致表明，`semantic_selector` 当前正式只支持 `title_like_paragraphs` 和 `body_like_paragraphs`。
- 当前差距：更多语义对象、更多字段同步、图层澄清协作与更复杂样本支持尚未进入稳定主口径。
- 验收口径：新增语义能力应延续当前分层策略，具备明确候选依据、结构化拒绝、审计字段与对应回归测试，而不是依赖隐式模型猜测。
- 阻塞判定：若新增语义请求只能退回模糊自然语言行为、重新出现不透明失败，或破坏现有 `E_SEMANTIC_TARGET_*` / `E_BODY_BASELINE_UNDERDETERMINED` 分层语义，则视为未闭环。

### P1：投影预算 / 降级 / 批次口径仍需统一收口

- 当前现状：`README.md` 已说明 `chat_projection`、`template_projection` 均支持预算、降级、批次与结构化 diagnostics；`docs/phase3-handoff.md` 已说明模板分类真实消费 `template_projection.batches`。
- 当前差距：当前仍需要把预算上限、降级顺序、批次解释、失败 surfaced 方式与宿主 / 文档口径进一步统一，避免不同入口对同一投影失败给出不同解释。
- 验收口径：chat / template / 宿主展示对投影摘要、降级结果、批次语义和阻断条件使用同一套定义，文档与测试同步更新。
- 阻塞判定：若相同输入在不同入口产生不一致的预算决策、降级说明或批次解释，且影响执行结果判断，则视为未闭环。

### P1：真实模型回归仍缺少“稳定验收”而非“单次可解释”口径

- 当前现状：当前真实模型测试已经接受“两类通过型结果”：
  - 成功产出 `output_docx_path`
  - 未产出文档，但命中当前白名单内的结构化失败
- 当前差距：这只能证明链路当前“可解释、可控”，还不能直接等价为真实模型链路已稳定完成。
- 验收口径：真实 provider 在核心样本上的结果应长期保持“成功输出或白名单结构化失败”，且不再出现 `reasoning_content` 回放兼容性错误或新的非白名单异常。
- 阻塞判定：出现非白名单结构化失败、非结构化失败、关键阶段缺失，或再次出现 `The reasoning_content in the thinking mode must be passed back to the API` 类错误。

### P2：`archive/legacy` 仅作过渡参考的收口策略尚未完成

- 当前现状：`README.md` 已将 `archive/legacy/` 定义为旧宿主、旧前端与旧 runtime 的归档目录，但当前系统说明仍保留“legacy 宿主兼容层 + 新主链”的过渡形态。
- 当前差距：哪些行为仍允许参考 legacy，哪些行为必须只以 `src/langgraph-ts` 和 handoff 为准，当前还缺少最终收口说明。
- 验收口径：`archive/legacy/` 仅保留迁移参考价值，不再承担当前行为定义；所有现行能力边界、验收口径与开发入口都以新主链文档和测试为准。
- 阻塞判定：如果排查或新增功能仍必须依赖 legacy 代码来解释“当前正确行为”，则说明过渡边界尚未收口。

## 当前统一判定

以下情况可视为“通过型真实链路”：

- 成功产出 `output_docx_path`。
- 关键阶段已按预期执行，例如 `write_tool`、`reconcile`、`materialize`。
- 未出现 provider `reasoning_content` 回放兼容性错误。
- 在真实模型 smoke / regression 场景下，即使没有 `output_docx_path`，只要返回当前白名单内的结构化失败，也应视为“受控失败”，而不是阻塞回归：
  - `E_GRAPH_RECURSION_LIMIT`
  - `provider_read_loop_exhausted`
  - `provider_tool_args_unmappable`
  - `set_settings_flag requires explicit settings patch targets`
  - `set_settings_flag requires settings`

以下情况视为阻塞型失败：

- 无 `output_docx_path`，且不属于当前白名单内的结构化失败。
- graph 中断，或未进入应到达的关键阶段。
- 再次出现 `The reasoning_content in the thinking mode must be passed back to the API` 类错误。
- 返回了既不产出文档、也不落在当前白名单内的非结构化失败。
- 已知现象升级为用户可见错误，导致最终文档不正确或请求无法完成。
