# **文档格式修改 Agent \- 前端工作台设计方案 (V1.2)**

## **核心设计原则**

* **极简色块化**：摒弃复杂的阴影和边框，使用高对比度的背景色块区分功能区域。
* **职能边界清晰**：左侧全局侧边栏专司“导航与路由”，右侧主区域专司“内容呈现与具体任务操作”。
* **交互直观化**：以“配置/勾选”代替“聊天指令”，降低文职人员的认知负担。
* **提示词拼接器模型 (Prompt Builder)**：前端表单、快捷指令框、自定义文本框本质上都是结构化提示词的收集器，统一拼接后发送给后端 Agent，保持前端逻辑轻量化。

## **一、 页面路由拓扑 (Page Routing Topology)**

采用 SPA (单页应用) 架构，根路由下通过侧边栏进行主要页面的切换。

\[App Root\] (根应用)
 └── \[Main Layout\] (全局基础布局)
      ├── \[Global Sidebar\] (左侧全局导航栏 \- 具备展开/收起状态)
      └── \[Main Content Container\] (右侧主内容容器)
           ├── Route: / (主页 \- 格式化工作台)
           ├── Route: /templates (模板库管理)
           ├── Route: /history (历史记录)
           └── Route: /settings (全局设置)

## **二、 页面组件层级拆解 (Hierarchical Breakdown)**

### **1\. 全局基础布局 (Main Layout)**

* **Layout Container**
  * **Sidebar Component** (左侧全局导航栏) \- *支持响应式收起为图标列表*
  * **Content Component** (右侧主区域)

### **2\. 左侧全局导航栏 (Global Sidebar)**

* **Sidebar Container**
  * **Header**
    * Atom: Menu Toggle Button (汉堡菜单/收起按钮)
    * Atom: Logo & App Name
  * **Primary Action Area**
    * Atom: Primary Button ("+ 新建任务")
  * **Navigation Menu** (导航项: 工作台, 模板库, 历史记录)
  * **Footer Navigation** (导航项: 设置, 用户信息)

### **3\. 主页 \- 格式化工作台 (Format Workspace)**

这是用户停留时间最长的核心工作区。采用“左内容辅助/右配置操作”的双栏布局。

* **Workspace Container**
  * **Header Section** (页面标题区)
  * *(条件渲染 A：当前无文件)*
  * **Upload Area Container** (文件拖拽上传区)
    * Atom: Dashed Border Box \+ Upload Icon \+ Text ("点击或拖拽 DOCX 文件至此")
  * *(条件渲染 B：文件已上传)*
  * **Task Processing Container** (任务处理区)
    * **Left Column: Document Context & Analysis** (左列：文档上下文与分析)
      * **File Info Card** (文件基本信息与替换按钮)
      * **Format Health Report Card** (格式健康检查简报)
        * Atom: Status Title ("发现 3 处格式不统一")
        * Atom: List Item ("正文存在宋体与微软雅黑混用")
        * Atom: List Item ("H2 标题缺失部分加粗")
      * **Document Outline Tree** (文档大纲视图 \- 提取 DOCX 结构)
        * Atom: Tree Node (H1, H2, H3 层级展示，辅助用户了解结构)
    * **Right Column: Prompt Builder Panel** (右列：格式配置提示词面板)
      * **Panel Header** (面板头部操作区)
        * Atom: Title ("格式配置")
        * Atom: Ghost Button ("恢复默认")
        * Atom: Ghost Button ("清空配置")
      * **Command Bar** (快捷指令/搜索框)
        * Atom: Input Box ("例如：将所有正文字体改为仿宋...")
      * **Config Accordion** (折叠配置组 1: 全局排版 \- 字体, 行距, 段前段后)
      * **Config Accordion** (折叠配置组 2: 标题层级 \- H1-H6 细节设置)
      * **Config Accordion** (折叠配置组 3: 快速模板下拉选择)
      * **Custom Requirement Area** (自定义需求文本区)
        * Atom: Textarea (多行文本框: "在此输入表单无法覆盖的复杂格式要求...")
  * **Bottom Action Bar** (底部操作吸顶栏)
    * Atom: Primary Button ("开始执行修改" \-\> 状态变为 "下载完整文档")

## **三、 核心操作逻辑定义 (Action Logic Definition)**

为避免状态混乱，以下按钮的职能边界与触发事件必须严格定义：

### **1\. 恢复默认 (Reset to Default)**

* **位置：** 右侧配置面板 Header。
* **职能：** 将所有**预设的表单选项**（如折叠组 1、2）恢复到系统初始推荐值或上次成功运行的通用值。
* **触发逻辑 & 事件：**
  1. 点击触发 Warning 弹窗：“是否覆盖当前表单配置？”（可选）。
  2. 确认后，清空 Command Bar 和 Custom Requirement Area 的输入。
  3. 将所有下拉框、单选框重置为默认常量配置对象 (Default Config Object)。

### **2\. 清空配置 (Clear All)**

* **位置：** 右侧配置面板 Header。
* **职能：** 清理用户的一切输入，回到一张“白纸”状态，适用于用户想完全手写指令或重新勾选的场景。
* **触发逻辑 & 事件：**
  1. 清空 Command Bar。
  2. 清空 Custom Requirement Area (多行文本框)。
  3. 将所有表单选项置为 None 或 不修改 状态（而非系统默认字体/字号）。

### **3\. 开始执行修改 (Execute Action)**

* **位置：** 底部操作栏。
* **职能：** 收集前端所有状态，构建最终的 Prompt / Config Payload，提交给后端 Agent。
* **触发逻辑 & 事件：**
  1. 冻结所有表单输入（置为 Disabled 状态）。
  2. 执行“提示词拼接逻辑” (Prompt Assembling Logic)：
     * 提取表单 JSON 数据。
     * 提取 Command Bar 文本。
     * 提取 Custom Requirement Area 文本。
     * 组合成统一的 Request Payload 发送给后端。
  3. 按钮转入 Loading 状态，展示进度。完成时跳转为“下载文档”状态。
